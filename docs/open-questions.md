## 1. 検索の初回だけは全文書を読む

解釈済みの文書を使い回すようにしたので、2 回目以降は速い（epub 10 冊で
108ms → 12ms。→ [design-notes.md](design-notes.md)）。**残っているのは初回**で、
そこは全文書を解釈するぶんそのままかかる。

真面目な索引（どの語がどのファイルにあるか）を持てば初回も消せるが、**索引は
ずれると嘘をつく**。いまの作りは「毎回すべてのファイルを見て、変わっていない
ものを読み直さないだけ」なので取りこぼしようがないが、索引にすると取りこぼしが
**「その語は無かった」と区別が付かなくなる**（打ち切りを必ず返しているのと同じ話）。
初回の重さと引き換えにする価値があるかは、**実際に重いと感じてから**決める。

## 3. スモークテストが CI でたまに落ちる

`test_the_glossary_filters_by_tag` が **v0.6.0 のリリースで落ちた**（623 passed /
1 failed。再実行では通ったのでフレーク）。`/glossary` を開いて `.card` が 15 秒
出てこない、という落ち方。手元と `check.cmd ci` では再現していない。

**この落ち方をする本物のバグを 1 つ見つけて直した**（カテゴリ管理が、読み込みの
前に開かれると「カテゴリがまだありません」のまま**描き直さない**）。応答を止めて
おく形の再現テストを足してあり、直す前は**まったく同じ「要素が 15 秒出てこない」**
で落ちる。手元では一瞬で返るので絶対に踏まず、負荷の高い CI でだけ出る類。

ただし**落ちたのは別のテスト**（`test_the_glossary_filters_by_tag`）なので、
**これが原因だったという証明にはならない**。残っている筋は「一覧の描画が
`/api/categories` と `/api/tags` の完了を待っている」こと —— どちらかが返って
こないと `.card` が永久に出ない。直すなら一覧を先に描いて絞り込みを後から
埋める形になるが、`?category=` の初期選択が効くまでに一度絞り込み無しの
一覧が見えるので、**見た目の代償のほうが大きい**。次に落ちたときに判断する。

**2 例目は原因が分かって、直した**（0.12.0 の作業中に 2 回踏んだ）。
`test_a_term_inside_the_popup_is_followed_in_place` が**テスト側の待ち方**を
間違えていた —— 吹き出しの中の語を辿ったあと `[data-pop-back]` が出たところで
中身を読んでいたが、**戻る道は読み込み中の描き方にも出る**（`paint()` の 1 か所に
置いてあるので 4 通りのどれでも戻れる、と決めてある側の帰結）。手元では読み込みが
一瞬で終わるので普段は通り、**重いときだけ「読み込み中…」を掴む**。
中身そのものを待つように書き直した。**フレークに見えたが、これは製品ではなく
テストの間違い**（この節の教訓どおり、回数ではなく待ち方を直した）。

見るための足場は入れてある:

- `page` fixture が JS の例外・console の error・通信の失敗を集めて出す（`_watch_page`）
- 一覧を待つのは `open_glossary()` 経由にした。`#list` が「busy でない かつ
  中身がある」まで待ち、**中身がエラーならその文言を持って落ちる** ——
  以前は読み込みが失敗しても素のタイムアウトになり、理由が残らなかった

**回数を増やすのではなくテストを決定的に書き直すこと**（`check.cmd ci` の
繰り返しは網であって証明ではない）。遅らせて再現するときも `sleep` ではなく
**応答を止めて手で通す** —— `sleep` で作った再現は、それ自体が次のフレークになる。

## 4. 時系列で「位置を手で直す」ことはできない

時系列そのものは入れた（→ [design-notes.md](design-notes.md)）。位置は毎回本文から
数えていて**保存していない**ので、ずれようがない代わりに**人が直す口が無い**。
残っているのはそこと、読書位置と繋ぐ話の 2 つ。

- **人が位置を手直ししたいとき。** `reveal` が本文にあるラベル（「第六章」「p.42」）
  で書けるなら、`Document.segments` から毎回引き直せるので**ずれない**。脆いのは
  **ラベルの無い文書（素のテキスト・Markdown）で位置を指したとき**だけ。ここに
  限って保存 + 版管理 + 補正が要る。設計は決めてある:
  - **版の鍵はハッシュ。** `read_cached()` の path + mtime + size は「読み直すか」の
    判定で、**内容が同じ保存し直しでも変わる**（補正を促す判定に使うと空振りする）。
    `documents.decode()` を通した**後**の本文のハッシュなら、文字コードや CRLF↔LF で
    版が変わらない。二段構えで安く済む（stat が同じ → 何もしない / 違う → ハッシュを
    取り、同じなら stat だけ更新）
  - **版が違ったら古い位置で並べない。** 「更新されています。補正してください」と
    出して順序を落とす。古い位置でそれらしく並べるのがいちばん危ない
  - **補正は報告を出す。推測で埋めない。**「同じ N 件 / 動いた M 件（前 → 後）/
    見つからなくなった K 件」。見つからないものは空にして残す（消さない）
  - **入り口は点検（`/doctor`）。**「直さないと読み手に見えないもの・黙って壊れて
    いるもの」を挙げる場所で、一段落してから自分で走らせる運びにも合う
  - **置き場所は frontmatter の外。** 派生データだし、`relations` は手で書ける形を
    保ちたい。**無くても壊れない**（時系列が出ないだけ）ようにする
- ~~「いま読んでいるところまでの関係だけ出す」~~ → **入れた。** 単位を揃えるのを
  やめ、**本文の自動リンクそのもの**で「出てきた語」を決めた（→
  [design-notes.md](design-notes.md)）。ここに残っているのは**位置を手で直す**話だけ

## 5. 相関図の「関係が書かれていない語」は、伏せた結果 0 本になった語まで含む

`splitLonely()` は**伏せたあとの辺**で数えているので、判明位置つきの関係しか
持たない語が「関係が書かれていない語」の帯へ落ちる。**関係は書いてあるので、
画面の文言が嘘になる**。

`samples/坊っちゃん` で実際に出る（既定の表示で うらなり・マドンナ・港屋・養源寺・
ターナー島 の 5 語が帯に並ぶが、この 5 語はいずれも関係を持っている）。

直すなら 2 通り:

- **数え方を変える**（伏せる前の辺で孤立を判定する）。ただし帯に落とさないと、
  辺の無いノードが段の中に浮いて図が横に広がる —— `splitLonely()` を足した理由が
  そこなので、代わりの置き場所が要る
- **文言を変える**（「いま出ている関係が無い語」など）。安いが、伏せていないときも
  その文言になる

**どちらにせよ「伏せたせいで落ちた語が何語か」は出したい** —— `hidden` の本数を
返しているのと同じ約束で、黙って別の見出しの下に置かない。

## 6. AI の応答が途中で切れると、そのまま失敗する

`parse_draft()` / `parse_candidates()` は JSON を取り出せなければ落ちる。
**応答が途中で切れた場合も同じ扱い**になり、502 が返るだけで引き直さない。

`samples/坊っちゃん` を作る途中で 1 回踏んだ（12 語のうち 1 語で、`definition` の
文字列が閉じないまま応答が終わった）。押し直せば通るので UI では致命的ではないが、
**まとめて登録**の途中で 1 語だけ落ちると分かりにくい。

`llm.TransientError` は**提供元の失敗**（503 / 429）を見ているので、ここは層が違う。
入れるなら「JSON として読めなかったときだけ 1 回引き直す」で、`_generate()` を
呼ぶ側（`ai.py`）の仕事になる。**恒久的な失敗まで引き直さない**線は同じ。

## 7. 相関図の中の文字だけは「文字の大きさ」に付いてこない

⚙ の **表示 → 文字の大きさ** は画面全体に効くが、**相関図の SVG の中だけは生の px の
まま**（→ [design-notes.md](design-notes.md)）。図には拡大縮小があるので手段はあるが、

- 塞ぐには、**CSS の px を JS 側の見積もりへ渡す**必要がある（`base.js` の

- **CSS だけ var 化するのがいちばん危ない。** 避けたはずのラベルが重なり、縦書きの

- 6 つの見せ方が同じ計算を使うので、直すなら 1 か所で済む —— 逆に、**どれか 1 つの

## 8. 地図の残り（関係につく座標・実在の地図・日記の動線）

**地図そのものは入れた** —— 相関図の 6 つめの見せ方 (`map.js`)。エントリに `map` と
形（点 `pin` / 線 `line` / 領域 `area`）を書くと絵の上に出る。絵は画面から入れられ、
出すものはチェックで選べ、名前を出すかも切り替えられる。決めたことと代償は
[design-notes.md](design-notes.md)、実物は `samples/戦国時代/`。

**「地図だけが既存の約束の外にいた」ぶんも塞いだ** —— 点検が地図を見る / 書き出しに
絵が入る（取り込みでは消さない）/ 重なった名前と一言を畳む / 用語ページに地図への
入口（→ [design-notes.md](design-notes.md)）。

**形は画面だけで作れるようになった** —— 頂点を足す / 消す、種別を変える（点 ⇄ 線 ⇄
領域）、地図から下ろす、そして**1 つ戻す**（保存が即時なので、消した頂点を取り返す道が
要る、というのがここに書いてあった宿題）。→ [design-notes.md](design-notes.md)

**関係につく時刻も入れた**（`when`。→ [design-notes.md](design-notes.md)）——
時系列が「読む順」と「作中の時刻」の 2 軸になり、**地図も時点で巻き戻せる**
（進軍路が順に伸びる）。**語自体にも時刻を書けるようにした**（→
[design-notes.md](design-notes.md)）—— 事件に 1 行書けば、その事件に繋がる関係は
まとめてそこに並ぶ（**前後は書かない。時刻から出る**）。

**確定しているものはもう残っていない。** 下の 3 つは、どれも「やるかどうか」から
決める必要がある（次に手を付けるなら、まずその判断から）。

### 人の位置は関係につく（諸説の並記・学術用途）

いま形（点・線・領域）を持てるのは**エントリ**だけ。地名も経路もそれで足りる ——
**説そのものを線にできる**ので、当初「関係に持たせるしかない」と書いた進軍路の分岐は
**エントリ側で解けた**。

残るのは**「同じ人物が事件ごとに違う場所に居た」を点として持ちたいとき**だけ。
信長の座標は「桶狭間・A説」の中でしか決まらないので、そこは関係の項目になる。
**ただし優先度は下がった** —— 地図に出したいものの大半は、いまの 3 つの形で書ける。

**排他ではなく役割が違う**（どちらか 1 つを選ぼうとしないこと）。田楽狭間がどこに
あるかは説に依らず（エントリ）、信長がそこへどう至ったかは説による（関係）。

**いまの形でどこまで書けるかは実物で確かめてある**（`samples/戦国時代/`）:

- **説はカテゴリではなくエントリにする。** カテゴリは辞書に対してフラットなので、
  説をカテゴリにすると**事件 × 説の直積**になる（絞り込みの選択肢がそれで埋まる）。
  カテゴリ「説」に説エントリを置けば、説 → 人 の関係がそのまま 2 段階になり、
  `matrix.js` の空きマスが**そのまま説の比較表**になる
- **説に依らない事実は「事件」が持つ。** 事件 → 説 だけにすると、今川義元が
  `ego.js` の半径 2 に入らない（事件から見れば主役なのに 3 ホップ）
- **`term` に事件名を含めない。**「桶狭間・迂回奇襲説」は本文にその表記が現れないので、
  登録してもリンクにならない
- **`rank`（上下）は説 → 人 には無い。** 陣営の中の上下は別軸で、人 → 人 に書く。
  混ざらないのは関係を起点のエントリが持つからで、**カテゴリで絞れば軸が切り替わる**
- ~~進軍路の分岐は引けない~~ → **引けるようになった。** 説は場所ではないが
  **経路そのもの**なので、説エントリに `line`（線）を書けば説ごとの進軍路が
  同じ地図に重なって出る（→ [design-notes.md](design-notes.md)）

~~**もう 1 つ、作るまで見えていなかったこと。** `rank` に時間が無い~~ →
**時刻は入れた**（関係の `when`。→ [design-notes.md](design-notes.md)）。
時系列に「作中の時刻」の軸が付き、**時期で立場が変わる人物**（徳川家康は今川義元と
織田信長の両方から指される）も、いつの関係なのかは書けるようになった。
**`rank` そのものは時間を持たないまま** —— 段の図は「いつの上下か」を選べないので、
そこは残っている（時刻で段を切り替える案は、まだ要る場面に当たっていない）。

~~**時系列をカテゴリごとに分ける案は保留。**~~ → **入れた**（→
[design-notes.md](design-notes.md)）。時系列に**並べるもの**の選択（関係 / 語）が付き、
語を選ぶと年表になる —— **軸に載るのは時刻のある語だけ**で、載らない相手はその行の
うしろに従として並ぶ。カテゴリで絞れば行に出る語をそのカテゴリだけにできるので、
「事件の年表」がそのまま作れる。**カテゴリ名の意味は読んでいない**（時刻を書くのは
事件、人物は期間なので書かない、という書き方の差が自然に主従を決める）。

**サーバ配置とアカウント別のアクセス制御**を求めるなら GlossPopApp の領域だが、
あちらは**コンシューマ（Web 小説）に決めたばかり**（→ [mobile-rethink.md](mobile-rethink.md)）。
学術路線を足すと「捨てるものの一覧が主役の選び方で変わる」で一度やった選び方を
もう一度やることになる。**3 つめの道具になりうる**ことも含めて保留。

### 実在の地図とタイル

いまは**画像 1 枚方式なので通信ゼロ**。実在の地図タイルを引くなら**外部通信の約束に
触る** —— タイルは**読んでいる場所そのものを配信元へ送る**（どの地名を見ているかが
漏れる）。やるなら**利用者が明示的に選んだときだけ + 画面に書く**（読み上げの
オンライン音声と同じ扱い）。そのときは Leaflet が初めて意味を持つ
（→ [design-notes.md](design-notes.md)）。

**こちらが配る絵だけ権利を気にする。** 国土地理院の地図にも OSM のタイルにも利用規約が
あるので、`samples/` に入れるのはパブリックドメインの古地図か自作に限る
（いまのサンプルは自作の SVG 略図）。利用者が用意するぶんは自由で、**画面から入れられる**
（→ [design-notes.md](design-notes.md)）。

### 日記の用途は後回しでいい

地名に日付が付いて、時系列と地図で自分の足取りを振り返る形。同じ仕組みには乗るが、
**「読んだものから抽出する」という主動線から外れる**（日記は自分で書くもの）。
**土台はもう入っている** —— 関係の `when` は時刻まで書けるので
（`2026-08-08 09:30 朝の散歩`）、あとは動線だけの話になった。

## 9. GlossPopApp をサーバ無しにするなら、起動の 7〜8 秒を受け入れるか

**サーバを運用しない方針**になり、`glosspop.core` がブラウザ（Pyodide）で**無改造の
まま動く**ことは実測で確かめた（→ [serverless-rethink.md](serverless-rethink.md)）。
照合の速さも問題にならない（moto g05 で 1 章 68 ms、長編 1 冊 0.5 秒）。

**残ったのは起動時間だけで、そこは測り切った。**

- **縮める余地**: g05 で 13.1 秒。削れるのは約 5 秒（パッケージの同梱と、`core` から
  pydantic を外すぶん）。**残る 7〜8 秒は WASM + CPython の初期化で、動かない床**
- **隠す余地**: Web Worker に置けば**画面の固まりは完全に消える**（主スレッドの停止は
  最長 1 フレーム）。ただし**待ち時間そのものは消えない** —— 温まる前に押した人は、
  残り時間ぶんそのまま待つ（5 秒後に押して 7.9 秒待ち）

**判断だけが残っている。** 受け入れる / 入口の動線を変えて温める時間を稼ぐ /
Pyodide をやめて Chaquopy（ネイティブ Python・Android 専用・+20〜40MB）にする。

保存先の候補（git リモート対 BaaS）と、URL 読み込みが殻を要求する理由も
serverless-rethink.md にある。**そちらは起動時間の判断が決まるまで動かせない。**
