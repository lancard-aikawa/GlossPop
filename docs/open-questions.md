## 1. 短い英字別名が意図しない箇所に当たる（要判断）

**症状**: 「Markdown」の別名 `MD` が、ファイル拡張子の `.md` に当たる。
README.md を開くと 5 箇所がリンクになる。

大文字小文字を区別しない照合と、境界チェックが「英数字以外なら通す」ため、
`.md` の `.` が境界として通ってしまう。インラインコードをリンク対象に加えたことで
表面化した（コード片には拡張子やオプション名が多い）。

**選択肢**:

1. **辞書側で対処** — 「Markdown」から別名 `MD` を外す。他の語に影響しない。
   ただし同種の別名（`ML`、`DB` など）を登録するたび同じ判断が要る
2. **照合規則を変える** — 全部大文字の短い ASCII 別名は大文字小文字を区別する。
   `MD` は当たるが `md` は当たらない。代わりに `API` を `api` と書いた箇所も
   当たらなくなる
3. **拡張子ガード** — 直前が `.` の ASCII 表記は無視する。狙いは正確に潰せるが、
   ルールとしては場当たり的

未着手。ユーザーの判断待ち。

## 2. 辞書一覧ページでの選択 → 登録

ビューアと用語ページには入れたが、一覧ページには入れていない。カードが `<a>` 全体
なので、ドラッグ選択がブラウザのリンクドラッグと競合して安定しない。
一覧には「＋ 新規登録」ボタンがあるので実害は小さい。

## 3. 辞書の件数が増えたときの性能

`load_all()` は全ファイルを読む（mtime キャッシュ付き）。`Linker` は全表記の
正規表現を毎リクエスト組み立てる。数百件なら問題ないが、数千件では両方が効いてくる。
必要になったら、Linker をエントリ集合のハッシュでキャッシュするのが最初の一手。

## 4. 複数端末での共有

いまは単一プロセス・ローカル前提（`store` の排他はスレッドロックだけ）。
共有するなら、ファイルロックか、そもそも git で同期する運用にするかを決める必要がある。

## 5. フロントエンドの自動テスト

無い。UI の回帰は Playwright で手動確認している。`select-add.js` の選択判定や
`popup.js` の配置ロジックは壊れやすいので、入れるならそこから。
