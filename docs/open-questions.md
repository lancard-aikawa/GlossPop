## 1. 辞書一覧ページでの選択 → 登録

ビューアと用語ページには入れたが、一覧ページには入れていない。カードが `<a>` 全体
なので、ドラッグ選択がブラウザのリンクドラッグと競合して安定しない。
一覧には「＋ 新規登録」ボタンがあるので実害は小さい。

## 2. 件数・分量が増えたときの性能

どれも「必要になったら」の枠で、いまは踏んでいない。

- `load_all()` は全ファイルを読む（mtime キャッシュ付き）。`Linker` は全表記の
  正規表現を毎リクエスト組み立てる。数百件なら問題ないが、数千件では両方が効く。
  最初の一手は Linker をエントリ集合のハッシュでキャッシュすること
- **横断検索は索引を持たず、その場で全文書を読む**（`MAX_SEARCH_FILES` で打ち切る）。
  epub や pdf の多いフォルダでは 1 回が重い。索引を持つならファイルの mtime で
  無効化する必要があり、辞書側と同じ作りになる

## 3. 複数端末での共有

いまは単一プロセス・ローカル前提（`store` の排他はスレッドロックだけ）。
共有するなら、ファイルロックか、そもそも git で同期する運用にするかを決める必要がある。

## 4. 辞書を「混ぜる」ことはできない

書き出しと取り込み（`archive.py`）は入れたが、取り込みは**置き換え**だけ。
別の PC の辞書と**併合する**、`1 カテゴリだけ渡す`、はできない。

置き換えにしたのは、同じカテゴリの同じ用語が両側にあったときにどちらを採るかを
決められないため（→ [design-notes.md](design-notes.md)）。併合を足すなら、
**衝突したときに何をするか**を先に決める必要がある。候補は 3 つ:

- 取り込む側を常に優先 — 単純だが、手元で直した内容が黙って消える
- いまある側を常に優先 — 安全だが、更新を持ち込む用途で使えない
- 1 件ずつ選ばせる — 正しいが、100 語の衝突を人が捌けるかは別の話

`updated_at` で新しいほうを採る手もあるが、**時計がずれている PC がある**と
静かに古いほうが勝つ。

## 5. Windows 以外の配布

`packaging/` は PyInstaller の Windows onedir だけ。macOS / Linux は「ソースから
動かす」しか道が無い。`appwindow.py`（ブラウザのアプリモード）と `picker.py`
（tkinter の別プロセス起動）は書き分けてあるので動きはするはずだが、**確かめていない**。

## 6. スモークテストが CI でたまに落ちる

`test_the_glossary_filters_by_tag` が **v0.6.0 のリリースで落ちた**（623 passed /
1 failed。再実行では通ったのでフレーク）。`/glossary` を開いて `.card` が 15 秒
出てこない、という落ち方。手元と `check.cmd ci` では再現していない。

**この落ち方をする本物のバグを 1 つ見つけて直した**（カテゴリ管理が、読み込みの
前に開かれると「カテゴリがまだありません」のまま**描き直さない**）。応答を止めて
おく形の再現テストを足してあり、直す前は**まったく同じ「要素が 15 秒出てこない」**
で落ちる。手元では一瞬で返るので絶対に踏まず、負荷の高い CI でだけ出る類。

ただし**落ちたのは別のテスト**（`test_the_glossary_filters_by_tag`）なので、
**これが原因だったという証明にはならない**。残っている筋は「一覧の描画が
`/api/categories` と `/api/tags` の完了を待っている」こと —— どちらかが返って
こないと `.card` が永久に出ない。直すなら一覧を先に描いて絞り込みを後から
埋める形になるが、`?category=` の初期選択が効くまでに一度絞り込み無しの
一覧が見えるので、**見た目の代償のほうが大きい**。次に落ちたときに判断する。

見るための足場は入れてある:

- `page` fixture が JS の例外・console の error・通信の失敗を集めて出す（`_watch_page`）
- 一覧を待つのは `open_glossary()` 経由にした。`#list` が「busy でない かつ
  中身がある」まで待ち、**中身がエラーならその文言を持って落ちる** ——
  以前は読み込みが失敗しても素のタイムアウトになり、理由が残らなかった

**回数を増やすのではなくテストを決定的に書き直すこと**（`check.cmd ci` の
繰り返しは網であって証明ではない）。遅らせて再現するときも `sleep` ではなく
**応答を止めて手で通す** —— `sleep` で作った再現は、それ自体が次のフレークになる。

## 7. 統合はできるが、併合（#4）の衝突には流用できない

割れてしまった同じものは `merge.py` でまとめられるようになった。ただしそこで
使った手（**衝突を並べて人に選ばせる**）がそのまま辞書の併合（#4）に効くとは
限らない。統合は 1 組 2 件だから確認画面が成立するのであって、**100 語が衝突する
併合で同じことをすると人が捌けない**。

併合をやるなら、**選ばせずに済む既定**を先に決める必要がある（→ #4）。
