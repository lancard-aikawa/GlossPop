# 設定の棚卸しと、そこで課題になってきたこと

> **これは観察と課題の一覧で、判断ではない。** 決めたことと理由は
> [design-notes.md](design-notes.md)、まだ「やるかどうか」から決めるものは
> [open-questions.md](open-questions.md) にある。**ここに写しを作らない** ——
> 同じことが 2 か所にあると、片方だけ古くなる。
>
> **調べた日: 2026-09-04。**

## 設定は 4 か所に散っている

| 置き場所 | 何が入るか | いつ効くか | 移せるか |
| --- | --- | --- | --- |
| **環境変数** | 全部（`GLOSSPOP_*` は 25 個） | 起動時 | — |
| **`settings.json`**（OS のユーザ領域） | `data_root` / `publish_dir` / `publish_base_url` / `ai_provider` / `ai_effort` / `gemini_api_key` / `update_check` | **項目による**（下記） | **運ばない**（アプリを入れ替えても残る側） |
| **`localStorage`**（ブラウザ） | テーマ・文字の大きさ・見せ方・読書位置・お気に入り・地図の状態など **23 個** | 押した瞬間 | `copy_data_root` が**運ぶ**（専用ウィンドウのプロファイルの中） |
| **`.glosspop/`**（フォルダごと） | 辞書・カテゴリマスター・文体 (`style.md`)・語り手の顔・地図の絵・用語の画像・**ファイルの画像** | 読むたび | **フォルダごとコピーすれば付いてくる** |

**優先順は「環境変数 > 設定ファイル > 既定」で統一されている。** 環境変数を最優先に
してあるのは、テストと一時的な切り替えが設定ファイルに引きずられないため。
壊れた設定ファイルでは既定に落ちる（起動できなくならないこと）。

## 「いつ効くか」が項目によって違う

これは**意図的に分けてある**が、画面から読めるようにしておく必要がある。

| 項目 | いつ | なぜ |
| --- | --- | --- |
| データの保存先 (`data_root`) | **次の起動から** | `config` は import 時に解決済みで、途中で差し替えると `store` のキャッシュや開いているフォルダと食い違う |
| 公開先 (`publish_dir` / `publish_base_url`) | **その場で** | 乗っているものが無い。待たせると「設定したのに書けない」になるだけ |
| AI（提供元・モデル・思考の深さ） | **その場で** | 同上 |
| 文体 (`.glosspop/style.md`) | **その場で**（毎回ファイルを開く） | 外のエディタで書き換えたぶんを黙って無視しないため |
| テーマ・文字の大きさ・最初の 1 回だけリンク | **押した瞬間** | ⚙ はビューアの上に重なって開くので、下の本文へすぐ効かせる |

## 繰り返し問題になってきたこと 6 つ

**1. 写しを作ると片方だけ古くなる。**
文体の欄を執筆ダイアログにも置きかけた（→ `.glosspop/style.md` と ⚙ が唯一の口）。
描画前に当てる設定（テーマ・文字の大きさ）は **6 つの HTML に写しがある**ので、
1 つ直し忘れるとそのページだけ効かない（スモークテストが開き直して見ている）。

**2. 保存の口を混ぜると「保存したのに効かない」になる。**
⚙ のフッタの「保存」は**データの保存先のもの**で、AI タブでは出さない
（AI 側は自前の保存ボタンを持ち、押した時点で効く）。

**3. 書き込みの口が増えると、開いただけのフォルダが汚れる。**
`.glosspop` を作りうるのは限られた口だけ（文体は `/api/ai/style` の 1 つ、
`/api/ai/settings` には載せない）。**ファイルの画像もその仲間**（`POST /api/file-image`）。

**4. 「決まっていない」状態をどう扱うかが項目ごとに違った。**
公開先はかつて**決めるまで書けなかった**が、`.publish/` を既定にして解消した
（→ design-notes）。**URL は今も「決まっていなければ空」**で、
そのときカードが出ないことは断りに出る。

**5. 覚えるものと覚えないものの線。**
見せ方・軸・深さ・地図の絵は覚えるが、**地図の時点**・**ここまで読んだぶん**・
**確認を省くかどうか**は覚えない（伏せたまま開き直すと「消えた」と読まれる、
前回の選択が黙って続くと 1 押しで十数語が入る）。

**6. 手元の環境が外へ漏れる経路。**
公開ページは `STRIP_KEYS` でフルパス・顔・画像の URL を落とす。
API キーは**返す口を作らない**（`/api/ai/settings` が返すのは「設定済みか」だけ）。

## 対象リポジトリの汚染 —— 起こった 2 つと、その場でやったこと

**「汚染」は 2 通りある。片方は履歴、もう片方は作業ツリー。**

### 1. 履歴 —— 並行セッションが、書きかけを巻き込んだ

**起こった事**（2026-09-04）。公開の設定を書いている最中に別のセッションが
コミットしていて、そこに**こちらの未コミットの `app.py` の変更が混ざった** ——
`/api/publish` に足した `default` と `guessed_base_url` の 2 つが、
`947f512「用語の画像を、本文から図を描いて作れるようにする」`の中に入っている。
図を描く機能とは無関係な変更。

同じ形の痕跡がもう 1 つある: `data/categories.yaml` は**セッション開始時点で
既に変更されていた**（利用者の動作確認か、別セッションの作業）。

**その場でやったこと**:

- **履歴は書き換えない。** 動いているものは動いているので、直すより
  「どこに何が入っているか」を残すほうを採った
- **自分が変えたファイルだけを名指しで stage する**（`git add -A` を使わない）。
  今回のコミットは 7 ファイルを名指しした
- **知らない変更は触らずに残し、出どころを言う。** `data/categories.yaml` は
  2 回のコミットともに外してある
- **コミットの本文にも書く。**「data/categories.yaml はこの作業のものではないので
  触っていない」

**残っている影響**: 公開設定の変更は**2 つのコミットに割れている**（`app.py` のぶんは
1 つ前）。あとから「この機能はどこで入ったか」を追うときに、`45bdcac` だけ見ても揃わない。

### 2. 作業ツリー —— 既定の書き出し先が、読んでいるリポジトリに現れる

**`.` で始めれば隠れる、は GlossPop の走査の話でしかない。git は普通に見る。**

公開の既定を `<開いているフォルダ>/.publish/` にした日に、この repo で穴が空いていた
—— `content/` は**追跡している**（`ようこそ.md` と `銀河鉄道の夜.txt`）のに、
`content/.publish/` は `.gitignore` に無かった。**既定のまま 1 回公開すれば、
生成物がそのまま `git status` に並ぶ**（辞書 1 枚 + 本文のページ + assets）。
`content/.glosspop/` は既に無視してあったので、**同じ理由の 2 つ目を漏らした**形。

**その場でやったこと**: `.gitignore` に `content/.publish/` を足した。

**これは利用者の側でも起きる。** 読んでいるフォルダが git リポジトリなら
（小説でもソースでも普通にありうる）、既定のまま公開すると**そのリポジトリに
未追跡のファイルが現れる**。あちらの `.gitignore` はこちらから触れない。

**まだやっていないこと**:

- **書き出し先が git リポジトリの中なら、そう言う。** `.git` があるかは
  `guess_base_url()` が既に見ているので、**判定は増えない**
- **`.gitignore` に 1 行足す案内を出す**（書くのは人。「元を消さない」「commit も
  push もしない」と同じ線で、こちらでは触らない）

## いま残っている課題

### 設定そのもの

- **`localStorage` の 23 個には、画面からまとめて消す口が無い。** 個別に戻す道はあるが
  （テーマを「システム」に、など）、**まとめて捨てる**口は無い。専用ウィンドウの
  プロファイルごと消せば消えるが、**お気に入りと読書位置も一緒に消える**
- **`settings.json` を人が読む形で見せていない。** ⚙ は項目ごとに出すだけで、
  いまファイルに何が書かれているかは画面から読めない
- **環境変数で固定されているとき、画面は「触らせない」までしかしていない。**
  どの値で固定されているかは出していない（キーだけは出さない、という線は正しい）

### 公開の設定（直近で触ったところ）

- **remote が複数あるときに片方しか候補に出ない。** `.git/config` に書いてある順で
  決まっていて、規則ではない —— **fork して作業している人は黙って片方に寄る**。
  候補を並べるところまでは読める範囲でできる（未着手）
- **リポジトリ一覧を GitHub から取る案は採らない。** 外へ出る口が 3 つ目になり
  （いまは `updates.py` と、利用者が明示的に選んだときの `llm.py` だけ）、
  **一覧は知りたいことに答えていない** —— どれが Pages として配信されているかは
  別のエンドポイントが要る。認証とレート制限も付く
- **書き出し先の階層が 1 つ余る**（`content/.publish/content/`）。サイトの名前は
  `og:site_name` と URL にも入る値なので、既定のときだけ畳むと形が 2 通りになる
- **切り替えると古い `.publish/` が残る。** `.` 始まりなので目に入らない。
  「元を消さない」の側だが、残っていることを画面に出すところまでは至っていない
- **書き出し先が git リポジトリの中でも黙っている**（→ 上の「対象リポジトリの汚染」）。
  `.git` を見ているのは `guess_base_url()` なので、判定そのものは増えない
- **貼った先の見え方は確かめられない**（→ [x-cards.md](x-cards.md)）。
  規約で決着したのは形式・クエリ・ページ 2 MB で、**拡張子の要否は書かれていない**

### 画面の側

- **本文の行の ✨ が 2 つ並ぶ**（用語を抽出 / 関係を下書き）。どちらを畳むかは
  **頻度の話**で、そこは使う人しか知らない（→ [ui-inventory.md](ui-inventory.md) の
  手順。棚卸し → 分類は人が決める → 規則 → 適用）
- **画像のフル表示が無い。** 既存に lightbox は無く、新しい部品になる。
  **要るかどうかは実物次第**（写真なら 640px で足り、原寸が要るのは地図や図解）
